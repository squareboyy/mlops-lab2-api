# Лабораторна робота №3: Моніторинг ML API та детекція проблем

[![CI Pipeline](https://github.com/squareboyy/mlops-lab2-api/actions/workflows/ci.yml/badge.svg)](https://github.com/squareboyy/mlops-lab2-api/actions/workflows/ci.yml)

## Опис системи
Цей проєкт є розширенням системи інференсу ML-моделей шаром комплексного спостереження (observability) та автоматичного контролю якості даних.
У рамках роботи веб-сервіс інструментовано метриками для збору Prometheus, налаштовано структуроване JSON-логування ключових подій інференсу, а також інтегровано статистичний детектор зсуву вхідних ознак (Data Drift) на основі двовибіркового критерію Колмогорова-Смирнова.

## Реалізовані ендпоінти та метрики
* **GET `/metrics`**: Ендпоінт у форматі Prometheus exposition format, що повертає зареєстровані метрики:
  * `ml_predictions_total` — лічильник кількості прогнозів із мітками за класами та статусом виконання.
  * `ml_prediction_latency_seconds` — гістограма розподілу часу обробки запитів.
  * `ml_prediction_confidence` — гістограма значень впевненості моделі (`predict_proba`).
  * `ml_errors_total` — лічильник виникнення внутрішніх помилок за типами.
  * `ml_model_loaded` — бінарний Gauge-індикатор стану доступності моделі в пам'яті.
  * `ml_drift_checks_total` та `ml_drift_detected_total` — метрики виконаних перевірок та зафіксованих подій зсуву даних.
* **POST `/check-drift`**: Приймає пакет (batch) спостережень та порівнює їхні поточні розподіли з еталонними даними навчання.

## Як запустити моніторинг локально
1. Переконайтеся, що ви перебуваєте у робочій гілці `lab3-monitoring`.
2. Перейдіть до каталогу інфраструктури моніторингу:
   ```bash
   cd monitoring
   ```
3. Підніміть повну інфраструктуру (сервіс API та інстанс Prometheus):
   ```Bash
   docker-compose -f docker-compose.monitoring.yml up --build
   ```

## Drift detection
Детекція зсуву даних (Data Drift) реалізована в модулі `app/drift.py` за допомогою класу `DriftDetector`. Детектор порівнює розподіл ознак у надісланому пакеті даних із розподілом на еталонній вибірці навчання (`reference_stats.joblib`).
* Для кожної з 4 числових ознак окремо розраховується двовибірковий тест Колмогорова-Смирнова через `scipy.stats.ks_2samp`.
* Якщо отримане значення `p_value` виявляється меншим за встановлений рівень значущості `alpha` (дефолтне значення `0.05`), для ознаки виставляється прапорець `drift_detected = True`.
* Загальний статус дрифту всього пакету вважається позитивним, якщо відхилення виявлено бодай в одній колонці.

## Приклади запитів

### Запит на інференс (POST `/predict`)
```bash
curl -X 'POST' \
  'http://localhost:8000/predict' \
  -H 'Content-Type: application/json' \
  -H 'accept: application/json' \
  -d '{
  "sepal_length": 5.1,
  "sepal_width": 3.5,
  "petal_length": 1.4,
  "petal_width": 0.2
}'
```
### Відповідь:
```json
{
  "class_id": 0,
  "class_name": "setosa",
  "probability": 0.9784
}
```

### Запит на перевірку дрифту (POST `/check-drift` — аномальний сценарій)
```bash
curl -X 'POST' \
  'http://localhost:8000/check-drift' \
  -H 'Content-Type: application/json' \
  -H 'accept: application/json' \
  -d '{
  "samples": [
    [9.0, 8.0, 8.0, 5.0], [9.5, 7.5, 8.5, 5.5], [8.5, 8.5, 7.5, 4.5],
    [9.2, 8.2, 8.2, 5.2], [9.8, 7.8, 8.8, 5.8], [8.8, 8.8, 7.8, 4.8],
    [9.4, 8.4, 8.4, 5.4], [9.6, 7.6, 8.6, 5.6], [8.6, 8.6, 7.6, 4.6],
    [9.1, 8.1, 8.1, 5.1], [9.3, 8.3, 8.3, 5.3], [9.7, 7.7, 8.7, 5.7]
  ],
  "alpha": 0.05
}'
```
### Відповідь:
```json
{
  "drift_detected": true,
  "n_drifted_features": 4,
  "drifted_features": ["sepal_length", "sepal_width", "petal_length", "petal_width"],
  "per_feature": { ... },
  "n_samples": 12,
  "alpha": 0.05
}
```

## Логування
Конфігурація структурованого логування налаштована в `app/logging_config.py` за допомогою `python-json-logger`.
Логи виводяться у стандартний потік `sys.stdout` в уніфікованому форматі JSON:
* **Приклад звичайного логу інференсу:**
  ```json
  {"timestamp": "2026-05-18T13:52:31.952Z", "level": "INFO", "logger": "ml-api", "message": "prediction_made", "predicted_class": "setosa", "confidence": 0.9784}
  ```
* **Приклад логу аномалії (Data Drift):**
  ```json
  {"timestamp": "2026-05-18T14:02:11.124Z", "level": "WARNING", "logger": "ml-api", "message": "data_drift_detected", "feature": "petal_length", "p_value": 0.0001}
  ```

## Висновки
У ході виконання роботи було успішно реалізовано шар спостережуваності (observability) для розгорнутого машинного навчання сервісу.
Інструментування метриками Prometheus дозволяє оперативно відстежувати як технічне здоров'я API (швидкість відповіді, частоту помилок), так і поведінкові тренди моделі (зміна частоти прогнозів певного класу чи падіння впевненості).
Додаткова інтеграція детектора Data Drift та звітів Evidently надає механізм виявлення "тихої деградації" моделі, спричиненої статистичним зміщенням реального вхідного потоку даних.
